# Bao Duong — Personal Project Journey

## Project

MediRun — EPITA RLA medical delivery planning prototype

## My Role

For this project, I contributed mainly to workflow review, testing, demo flow, presentation support, and usability feedback. My role was to help check whether the prototype made sense from the user's point of view and whether the final demo could be explained clearly.

I also worked with Minh on reviewing the manager and driver workflow, and I helped the team identify areas where the interface or project explanation needed to be clearer.

## How I Started

At the start of the project, I joined the group discussions about the client problem and the type of prototype we should build. The project needed to show a real operational problem, so I helped think about the workflow from the manager's side and the driver's side.

The main question was whether the app flow would be understandable during a demo: could a manager log in, see the day, review routes, and then could a driver log in and follow their own route?

## What I Worked On

## Workflow Review

I helped review the main workflow of the prototype:

- manager login
- dashboard overview
- weekly plan
- deliveries and fleet pages
- suggested plan review
- plan confirmation
- driver route view
- driver status updates

This helped the team check that the prototype was not only functional, but also understandable.

## Testing

I supported testing by checking the demo flow and looking for confusing parts of the interface. Testing was important because the app had different roles and several pages.

The main things checked during testing were:

- manager pages load correctly
- driver pages only show driver-specific routes
- routes are shown clearly
- status buttons make sense
- warnings are visible
- the final workflow can be demonstrated without too much explanation

## Presentation And Demo Support

I helped with the presentation direction by reviewing what should be shown during the final demo. The goal was to make sure the group could explain the project clearly:

- what problem MediRun solves
- why Monday is important
- why refrigerated deliveries matter
- how the manager keeps control
- how drivers use the route page
- what the future improvements are

## Workflow Review With Minh

I worked with Minh on checking the user flow and page structure. Since Minh worked strongly on the client interview and frontend side, we discussed how the client answers should appear in the final workflow.

This helped make the manager flow more realistic, especially after the client clarified that the system should suggest a plan but not fully decide everything automatically.

## What I Learned

This project helped me understand that testing is not only about finding code errors. It is also about checking whether the workflow makes sense for the user.

I learned that:

- a working feature still needs to be easy to explain
- manager and driver roles must be clearly separated
- a demo flow should be simple and logical
- client requirements can change the direction of the prototype
- usability feedback helps make a project feel more complete

## Problems I Faced

One challenge was understanding the full project because it included backend, database, frontend, and documentation. To help with testing and presentation, I needed to understand the complete flow, not only one page.

Another challenge was making sure the demo did not feel confusing. Since the manager has several pages, the workflow needed to be reviewed carefully so the audience could follow it.

## How I Worked With The Team

The team worked together through discussion and review. Victor handled more of the backend, database, planning logic, and coordination. Minh focused strongly on the client interview, client notes, HTML/frontend structure, and data requirements.

I supported the project by reviewing workflow, testing the prototype, checking usability, and helping prepare the demo explanation. I also gave feedback on how the manager and driver pages should feel during the presentation.

## Final Reflection

My main contribution was helping make sure the final prototype was understandable and demo-ready. MediRun is not only a coding project; it also needs a clear user story.

The final workflow is stronger because the manager can review and confirm route suggestions instead of the system deciding everything automatically. This makes the prototype closer to the client need.

If I had more time, I would help improve the testing checklist, add more screenshots for the presentation, and make the user flow even clearer for someone seeing the project for the first time.
